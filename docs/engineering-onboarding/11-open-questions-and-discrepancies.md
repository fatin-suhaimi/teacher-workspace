## Shortlist for maintainers

The questions most worth asking, in priority order. Answers would resolve the largest documented gaps.

0. **Q45 (blocks the Edupass integration test):** Edupass requires `response_mode=form_post`, and the server neither requests it nor accepts a POST callback. No open issue covers the server side. Who owns it, and can it land before the integration test?
1. **Q21 / Q8 / Q38:** `/api/` now requires a signed-in user with a role and passes role and attributes (#212). Is a subject claim (`sub`) planned, should signed-out callers get 401 instead of 500, and is CSRF enforcement planned before partner backends hold real data? How should remotes obtain the CSRF token?
2. **Q26 (narrowed):** Sign-in now enforces one base role from Edupass `groups` (#199, #202). Open: should location be kept, and should the shell vary by role?
3. **Q22 / Q27:** Is "no logout, 30m idle timeout, no absolute lifetime" the agreed session policy (shared school devices)?
4. **Q29 / Q11 / Q35:** The infra repo shows no edge security headers, a `GET /` health check and no TW-specific monitoring. Are these to be added in the app or the platform?
5. **Q1:** Is the ADR-0001 developer image (host, backend, datastores, local IdP) still planned, or built elsewhere?
6. **Q40 / Q12:** Does the CI Format job actually fail on unformatted code? Is skipping host typecheck and mock tests in CI intentional?
7. **Q41 / Q42 / Q3:** Happy to receive small docs PRs for `CONTRIBUTING.md` (third process, full remote env vars) and the mock-edupass README variable names?
8. ~~**Q4:**~~ Resolved by #204: the Go module is now `github.com/transformteamsg/teacher-workspace`, matching the AWS push role's `transformteamsg/*` trust (infra IQ10).
9. **Deployment (infra track):** the dev and stg task definitions use variable names this revision ignores (infra IQ2). See `infra/13-infra-session-handoff.md` for the prioritised infra list.
